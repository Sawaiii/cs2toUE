# cs2toUE

Конвертер демок Counter-Strike 2 в Unreal Engine: движение игроков, гранаты, события,
эффекты, камеры и **геометрия карт** — всё это превращается в готовый Level Sequence,
с которым можно работать как с обычной анимацией.

Программа не изобретает свой парсер и свой декомпилятор. Она связывает готовые открытые
инструменты и берёт на себя всю рутину: какая версия HLAE нужна под конкретную демку, где
в игре лежат карты и модели, что уже сконвертировано, где в матче интересные моменты, как
пересчитать координаты Source в координаты Unreal.

| Задача | Инструмент |
|---|---|
| Хук в игру, камера, запись | [HLAE / advancedfx](https://github.com/advancedfx/advancedfx) — программе доступны все 411 релизов |
| Парсинг демок CS2 | [demoparser2](https://github.com/LaihoE/demoparser) (ядро на Rust) |
| Декомпиляция карт и моделей | [Source 2 Viewer / ValveResourceFormat](https://github.com/ValveResourceFormat/ValveResourceFormat) → glTF |
| Сборка сцены | Unreal Engine Python API (Level Sequence) |
| Камеры туда и обратно | формат HLAE `.cam` (`mirv_camio`) |

---

## Что умеет

**Разбор демки**
- Читает заголовок любой демки CS2 (`PBDEMS2`) и CS:GO (`HL2DEMO`) без сторонних библиотек:
  карта, тикрейт, длина, номер сборки игры, таблица раундов.
- Подбирает подходящую версию HLAE и ставит её; версии живут рядом друг с другом.
- Запускает демку в игре через нужный HLAE одной командой.

**Поиск интересного**
- Находит эйсы, мультикиллы, клатчи 1vX, убийства ножом/зевсом/гранатой, дефьюзы —
  с готовыми диапазонами тиков.
- Показывает сцену сверху с таймлайном: выбрать момент можно глазами, а не по таймкодам.

**Экспорт**
- Треки движения игроков и гранат, события, эффекты — в компактный формат из `scene.json`
  и CSV-треков.
- Камеры пяти типов со сглаживанием, пригодным для съёмки.
- Карты и модели игроков из установленной игры — в glTF, с кэшем: одна карта собирается
  один раз.

**Unreal Engine**
- Собирает Level Sequence: акторы, transform-треки, видимость мёртвых, CineCamera с
  камерным катом и фокусным расстоянием из FOV, маркеры раундов и убийств на таймлайне.
- Расставляет эффекты: дым, молотовы, взрывы, флешки, трассеры выстрелов.
- Кладёт анимации на Skeletal Animation Track — без Animation Blueprint, всё видно и
  правится руками.

**Обратно в CS2**
- Любая камера пишется в `.cam`, то есть тот же пролёт можно проиграть в игре через
  `mirv_camio import` и снять уже средствами HLAE.

## Установка

Один файл — **`cs2toUE-Setup.exe`** (57 МБ), лежит прямо в корне папки рядом с этим
README. Больше ничего не нужно: Python, `demoparser2` и `pandas` уже внутри него.

Запустите его, выберите папку — установщик покажет, сколько места нужно и сколько
свободно, скопирует программу, **скачает HLAE и Source 2 Viewer** (галочку можно снять),
создаст ярлык на рабочем столе и в меню «Пуск», зарегистрирует программу в «Приложения и
возможности» и положит рядом `Uninstall.cmd`. Установка занимает около минуты, после неё
догружать больше нечего.
**Права администратора не нужны.** Папка по умолчанию — стандартная для программ,
устанавливаемых без администратора: `%LOCALAPPDATA%\Programs\cs2toUE`. Её можно поменять
на любую, в том числе на другом диске.

После установки:

- **`cs2toUE.exe`** — окно программы (ярлык `cs2toUE`);
- **`cs2toue-cli.exe`** — та же программа в консоли: `cs2toue-cli.exe inspect match.dem`.

Установка без вопросов (для скриптов и удалённых машин):

```bat
cs2toUE-Setup.exe --silent --target=D:\Programs\cs2toUE
cs2toUE-Setup.exe --silent --no-shortcuts --no-tools --log=setup.log
```

`--no-tools` пропускает загрузку HLAE и Source 2 Viewer — они докачаются при первом
использовании (пригодится, если на машине нет интернета).

Удаление — из «Приложения и возможности», ярлыком «Удалить cs2toUE» или файлом
`Uninstall.cmd` в папке программы. Папка `workspace` при удалении не трогается: в ней
лежат скачанные сборки HLAE, сконвертированные карты и экспортированные сцены.

### Обновления

Программа следит за релизами сама: раз в сутки спрашивает GitHub, и если вышла новая
версия — в окне появляется кнопка «Обновить».

Обновление скачивает **только файлы программы** (45 МБ вместо 57 МБ установщика) и
подменяет их на месте. Не трогается ничего вашего:

- `workspace` — сборки HLAE, сконвертированные карты и модели, экспортированные сцены;
- настройки (пути к CS2, движку и проекту Unreal);
- ваши пины версий HLAE в `data\hlae_rules.json`.

```bat
cs2toue-cli.exe update --check    :: что доступно и что нового
cs2toue-cli.exe update --yes      :: обновиться без вопросов
```

Запущенная программа не может перезаписать сама себя, поэтому подмену делает маленький
помощник: он ждёт, пока `cs2toUE.exe` и `cs2toue-cli.exe` закроются, копирует файлы,
пишет результат в `workspace\update\update.log` и запускает программу заново.

### Сборка из исходников

```
powershell -ExecutionPolicy Bypass -File build.ps1
```

Один скрипт делает всё с нуля: находит рабочий Python (**если его нет — скачивает и
ставит Python 3.13 внутрь папки проекта**, без прав администратора), создаёт venv,
ставит зависимости и PyInstaller, собирает приложение и упаковывает его в установщик.

Результат — **`cs2toUE-Setup.exe` в корне папки проекта**, рядом с `README.md`. Больше
ничего наружу не кладётся: промежуточная сборка приложения уходит в
`workspace\build\app\cs2toUE\` и нужна только сборщику. Флаг `-AppOnly` собирает одно
приложение, без установщика.

Запуск из исходников без сборки: `workspace\venv\Scripts\python.exe -m cs2toue <команда>`.

Выпуск новой версии — одной командой:

```
powershell -ExecutionPolicy Bypass -File build.ps1 -Publish
```

Номер версии берётся из `cs2toue/__init__.py` и становится тегом релиза. В релиз кладутся
оба файла: `cs2toUE-Setup.exe` для новых установок и `cs2toUE-app.zip` для встроенного
обновления (имя архива менять нельзя — по нему обновление и ищет файл). Если релиз с таким
тегом уже есть, файлы в нём заменяются. Нужен GitHub CLI — свой или в
`workspace\tools\gh\`.

### Куда всё ложится

Всё, что программа скачивает и создаёт — HLAE, карты, модели, экспортированные сцены —
лежит в папке `workspace` **рядом с программой**. То есть диск выбирается один раз, при
установке: поставили на D — всё будет на D.

Под карты и сборки движка может уйти несколько гигабайт, поэтому если на системном диске
тесно, ставьте программу на другой. Установщик проверяет свободное место и не даст
установить туда, где его нет.

Отдельный случай: если поставить программу в защищённую папку (`C:\Program Files`),
записывать рядом с собой она не сможет — тогда `workspace`, настройки и загрузки
автоматически уезжают в `%LOCALAPPDATA%\cs2toUE`.

Проверить состояние и место:

```bat
cs2toue-cli.exe doctor
cs2toue-cli.exe usage
```

Размеры: сразу после установки ~306 МБ (программа 101 МБ, Source 2 Viewer 122 МБ,
HLAE 24 МБ, скачанные архивы 59 МБ — их можно удалить командой `clean --downloads`).
Дальше растёт от карт: одна карта — сотни мегабайт.

## Быстрый старт

```bat
cs2toue-cli.exe inspect match.dem                  :: что за демка и какой HLAE ей нужен
cs2toue-cli.exe clips   match.dem                  :: где в матче эйсы, клатчи, мультикиллы
cs2toue-cli.exe maps convert --demo match.dem      :: карта демки → glb (один раз, дальше из кэша)
cs2toue-cli.exe export  match.dem --clip-id 1      :: лучший момент → сцена + сглаженная камера

cs2toue-cli.exe ue set --engine "S:\ue5\UE_5.5" --project "S:\work\My.uproject"
cs2toue-cli.exe ue build workspace\exports\match_clip1_ace
cs2toue-cli.exe ue render workspace\exports\match_clip1_ace   :: кадры PNG без открытия редактора
```

То же самое в окне — `cs2toUE.exe` (или ярлык `cs2toUE`).

## Как это работает

```
   match.dem
      │
      ├─ demoinfo ──────► заголовок: карта, тики, раунды, номер сборки
      │                        │
      │                        └─► hlae.resolver ──► нужная версия HLAE ──► play в CS2
      │
      ├─ highlights ────► список моментов (эйсы, клатчи, ножи, дефьюзы)
      │
      ├─ demoparser2 ───► треки игроков и гранат + события
      │                        │
      │                        ├─► effects ──► дым, молотовы, взрывы, трассеры
      │                        └─► cameras ──► сглаженная камера ──► .cam для CS2
      │                                │
      │                                ▼
      │                        scene.json + tracks/*.csv
      │                                │
   CS2 install                         ▼
      ├─ maplib ───► Source 2 Viewer ──► карта .glb ──┐
      └─ models ───► Source 2 Viewer ──► модели .glb ─┤
                                                      ▼
                                          Unreal Python API
                                       (build_sequence / import_map)
                                                      │
                                                      ▼
                                              Level Sequence
```

### 1. Заголовок демки читается своими руками

Первое, что нужно сделать, — понять, какая это демка, и это должно работать **до** того,
как что-либо установлено. Поэтому чтение заголовка написано на голой стандартной
библиотеке: маленький сканер protobuf достаёт из демки `CDemoFileHeader` и `CDemoFileInfo`.
Оттуда сразу известны карта, тикрейт, длина и, что важно, **таблица стартовых тиков
раундов** — бесплатно, без разбора всей демки.

### 2. Версия HLAE выбирается по установленной игре, а не по демке

Здесь путаются чаще всего. HLAE — это хук в **запущенную игру**, а не читалка демок.
Значит:

- демка CS:GO (`HL2DEMO`) требует `AfxHookSource` и клиента CS:GO;
- демка CS2 (`PBDEMS2`) требует `AfxHookSource2`, и релиз не должен быть новее вашего
  клиента.

В changelog HLAE есть пометки вида `Adjusted to CS2 update (1.41.6.8)`. Программа держит
индекс всех релизов с этими пометками, сравнивает их с `PatchVersion` из вашего
`game/csgo/steam.inf` и берёт самый свежий релиз, который ещё не «переехал» на более новый
патч игры. Релизы без пометки наследуют требование предыдущего. Пре-релизы в
автоподборе пропускаются.

### 3. Сцена — промежуточный формат, а не сразу Unreal

```
<сцена>/
    scene.json          мета, акторы, раунды, события, эффекты
    tracks/<актор>.csv  по треку на игрока, гранату и камеру
    camera_follow.cam   камеры в формате HLAE
```

Треки лежат **в координатах Source** (юниты, QAngle, тики) — пересчёт делает скрипт на
стороне движка, где масштаб выбирает пользователь. CSV выбран намеренно: он потоковый,
читается стандартной библиотекой внутри Unreal и его видно глазами.

Колонки: `tick, time, x, y, z, pitch, yaw, roll, fov, alive, health, weapon, duck, speed`.
Последние две нужны, чтобы в Unreal было чем выбирать анимацию.

### 4. Координаты

Source — правая система координат (+Y влево), Unreal — левая (+Y вправо). Отсюда:

```
позиция:  (x, -y, z) * scale
углы:     pitch = -pitch,  yaw = -yaw,  roll = +roll   ← roll знак НЕ меняет
масштаб:  1 юнит Source = 1 дюйм = 2.54 см = 2.54 uu   (--scale=2.54, по умолчанию)
```

Знак `roll` выведен из матриц поворота обоих движков, а не подобран: зеркалирование по Y
меняет знак только у pitch и yaw. `--scale=1.0` — если карта импортирована в «сырых»
юнитах Source.

### 5. Всё тяжёлое кэшируется

Карты, модели, списки содержимого архивов игры и найденные моменты складываются в
`workspace` с ключом по размеру и дате исходного файла. Одна карта собирается один раз;
пересборка — только если Valve обновила `.vpk` или указан `--force`.

## Версии HLAE

```bat
cs2toue-cli.exe hlae resolve match.dem     :: какая версия нужна и почему
cs2toue-cli.exe hlae list --limit 20       :: список релизов (* = уже скачан)
cs2toue-cli.exe hlae install 2.185.0       :: поставить конкретную версию
cs2toue-cli.exe hlae installed             :: что стоит локально
cs2toue-cli.exe hlae refresh               :: обновить индекс прямо сейчас
```

**Индекс релизов обновляется сам.** HLAE выходит часто, поэтому список версий
перечитывается с GitHub, если локальной копии больше суток — при открытии окна и перед
любой командой, которая с ним работает. Нет сети — берётся последняя сохранённая копия,
программа не ломается. Возраст индекса видно в `doctor`.

### Какая версия игры в демке

`inspect` показывает не только саму демку, но и на какой версии CS2 она записана:

```
game
  версия демки   CS2 1.41.5.4, сборка 2000797, 2026-04-22
  ваш клиент     CS2 1.41.7.5   старше вашего клиента — обычно такие демки CS2 проигрывает нормально
  HLAE той эпохи 2.189.9   (вышел 2026-04-22) — если проигрывать демку на клиенте того времени
  под эту версию 2.190.0   — новейший HLAE, ещё не перешедший на более новый патч игры
```

Откуда данные: в заголовке демки есть номер сборки, а changelog HLAE оперирует версиями
вида `1.41.6.8`. Мост между ними — таблица `data/cs2_versions.json`, собранная из истории
`game/csgo/steam.inf` в [GameTracking-CS2](https://github.com/SteamDatabase/GameTracking-CS2):
**381 обновление игры с марта 2023 года**, каждое со сборкой, версией патча и датой.
Таблица дополняется сама, если ей больше недели.

Сопоставление намеренно осторожное: номер сборки сверяется со всеми идентификаторами
таблицы, и если ничего не совпало — так и пишется, «версия не опознана», а подбор HLAE
идёт по вашему клиенту. Неверно угаданная версия игры дала бы неверную рекомендацию
HLAE, это хуже честного «не знаю».

**Версию можно выбрать руками.** В окне рядом с блоком HLAE есть список: первой идёт
подобранная программой (помечена «рекомендуется»), дальше все подходящие релизы с датой,
пометками «скачана», «CS2 1.41.6.8» (к какому патчу игры адаптирован) и «pre» для
пре-релизов. Выбранная версия и ставится, и используется для запуска демки. Для демки
CS:GO список автоматически сужается до сборок с `AfxHookSource`.

В консоли то же самое даёт флаг `--hlae`:

```bat
cs2toue-cli.exe play match.dem --hlae 2.190.2
cs2toue-cli.exe inspect match.dem --hlae latest
```

Версии живут рядом в `workspace\hlae\<версия>\`, поэтому демка 2023 года и сегодняшняя
получают каждая свою.

Если опытным путём выяснили, что для определённых демок нужен конкретный HLAE — запомните
это, и дальше он будет подбираться сам:

```bat
cs2toue-cli.exe hlae pin 2.185.0 --engine source2 --build 14000-14099 --note "проверено"
```

Правила лежат в `data\hlae_rules.json`, их можно править руками.

Запуск демки в игре:

```bat
cs2toue-cli.exe play match.dem
cs2toue-cli.exe play match.dem --camio out\shot.cam     :: сразу писать камеру
cs2toue-cli.exe play match.dem --exec "mirv_fov 90"
cs2toue-cli.exe play match.dem --dry-run                :: показать команду, не запуская
```

Команды игре передаются через сгенерированный `.cfg`, поэтому пути с пробелами и кавычками
не ломаются.

## Хайлайты

Программа читает игровые события (без потиковых данных — это пара секунд даже на длинном
матче) и находит интересное:

```
cs2toue-cli.exe clips match.dem
```

```
14 moments in match.dem (map de_dust2)
  [ 1]  21:14  ace       12.4s  5k Player1 (round 14)
          Enemy2 (ak47, hs)
          Enemy4 (ak47, wallbang)
  [ 2]  33:02  clutch    18.1s  clutch 1v3 Player7 (round 21)
          alone against 3, 3 kills to win the round
  [ 3]   8:40  special    9.0s  knife kill Player3 -> Enemy1 (round 5)
```

Что ищется: эйсы и мультикиллы (с расшифровкой каждого убийства — оружие, `hs`,
`wallbang`, `noscope`, `smoke`, `blind`), клатчи 1vX по реальному подсчёту живых (стороны
команд считываются один раз на раунд), убийства ножом/зевсом/гранатой, дефьюзы с остатком
времени на бомбе.

Каждый момент — готовый диапазон тиков с запасом до и после (`--pre`, `--post`),
отсортированный по значимости, с дедупликацией вложенных клипов. Результат кэшируется.

```bat
cs2toue-cli.exe clips match.dem --min-kills 2       :: включая даблкиллы
cs2toue-cli.exe clips match.dem --json              :: для своих скриптов
cs2toue-cli.exe export match.dem --clip-id 2        :: экспортировать момент №2
```

## Превью

```
cs2toue-cli.exe preview <сцена>
```

Вид сверху с таймлайном: следы всех игроков, живые и мёртвые, направление взгляда, гранаты,
дымы и молотовы своими радиусами, трассеры. Внизу — время, тик и события рядом
(`kill: Shooter → Victim (ak47)`).

- пробел — играть/пауза, стрелки — по кадру, скорость 0.25×…4×;
- `I` и `O` — отметить начало и конец, «Copy range» кладёт в буфер готовую команду
  `cs2toue export "<демка>" --from <тик> --to <тик>`;
- клик по игроку — выбрать его (показывает steamid для `--target`).

## Экспорт сцены

```bat
cs2toue-cli.exe export match.dem                       :: вся демка, 30 fps
cs2toue-cli.exe export match.dem --round 12            :: один раунд
cs2toue-cli.exe export match.dem --clip-id 3           :: найденный момент
cs2toue-cli.exe export match.dem --clip 12:30-13:10    :: отрезок по времени
cs2toue-cli.exe export match.dem --fps 60
cs2toue-cli.exe export match.dem --map                 :: заодно сконвертировать карту
```

Длинная демка — это миллионы ключей, поэтому экспортируйте момент или раунд, а не 40 минут
целиком. Прочие флаги: `--no-grenades`, `--no-events`, `--max-players`, `--out`.

## Камеры

Сырые данные дёрганые: игрок вертит мышью на каждом тике, и всё это попадает в трек.
Поэтому камера строится в два этапа — сначала путь, потом сглаживание: позиции гауссовым
окном, **углы через единичные векторы**, чтобы переход 179° → −179° никогда не давал
прокрут.

| риг | что делает | сглаживание по умолчанию |
|---|---|---|
| `pov` | от глаз игрока (учитывает присед) | 0.12 с |
| `follow` | сзади-сверху, наклон гасится на 65 % | 0.45 с |
| `orbit` | облёт вокруг цели | 0.25 с |
| `static` | неподвижная точка, следит за целью | 0.30 с |
| `action` | центр между целью и ближайшим живым противником, отход перпендикулярно линии между ними | 0.60 с |

```bat
cs2toue-cli.exe camera <сцена> --rig follow
cs2toue-cli.exe camera <сцена> --rig pov --target Player1
cs2toue-cli.exe camera <сцена> --rig orbit --orbit-speed 40
cs2toue-cli.exe camera <сцена> --rig action --smooth 0.8 --fov 65
```

`--target auto` выбирает игрока из клипа, иначе того, кто больше всех убивает на отрезке.
Настройки: `--smooth`, `--fov`, `--distance`, `--height`, `--orbit-speed`, `--name`.

Камера попадает **и в сцену, и в `.cam` рядом**, поэтому один и тот же пролёт можно:

- собрать в Sequencer: `cs2toue ue build <сцена>`;
- проиграть в CS2 и снять через HLAE: `mirv_camio import start "<файл>.cam"`.

В окне это выпадающий список `camera` рядом с экспортом и кнопка «Rebuild camera» —
пересобрать камеру с другими параметрами на готовой сцене, не разбирая демку заново.

## Библиотека карт

Программа сама находит карты в папке CS2 (включая карты из мастерской), конвертирует их в
glTF и **запоминает результат**. Никакой массовой конвертации при выборе папки не
происходит — только по вашей команде.

```bat
cs2toue-cli.exe maps list                                  :: что есть и что уже готово
cs2toue-cli.exe maps list --cs2-dir "D:\Steam\steamapps\common\Counter-Strike Global Offensive"
cs2toue-cli.exe maps convert de_dust2 de_mirage
cs2toue-cli.exe maps convert --demo match.dem
cs2toue-cli.exe maps path de_dust2
cs2toue-cli.exe maps remove de_dust2
```

Готовые карты: `workspace\maps\<карта>\`, реестр — `workspace\maps\library.json`.
Импорт в проект: `cs2toue-cli.exe ue map de_dust2`.

## Модели игроков

По умолчанию в Unreal встают цилиндры. Чтобы вместо них были агенты CS2:

```bat
cs2toue-cli.exe models list --filter ctm          :: ищется прямо в архивах игры
cs2toue-cli.exe models export ctm_sas tm_phoenix  :: в glb со скелетом и анимациями
cs2toue-cli.exe models library
cs2toue-cli.exe ue models --scene <сцена>         :: импорт в проект + ue_mapping.json
```

Пути моделей не захардкожены: содержимое `pak01_dir.vpk` листается и фильтруется, поэтому
переименования после патчей ничего не ломают. Имена анимаций читаются прямо из glb.

Анимация собирается **без Animation Blueprint** — секциями на Skeletal Animation Track,
поэтому всё видно на таймлайне и правится руками. Клипы выбираются так, как это делает
сама игра:

| состояние | условие | клип |
|---|---|---|
| `death` | игрок мёртв | death, до конца клипа |
| `jump` | `is_airborne` из демки | jump |
| `crouch_idle` / `crouch_walk` | `duck > 0.5` | crouch, по направлению |
| `run` / `walk` | по скорости | **8 направлений**: бег правым боком играет `run_E`, спиной — `run_S` |
| `fire` | событие `weapon_fire` | короткая секция поверх локомоушена |
| `idle` | остальное | idle |

Направление движения — это `move_yaw − yaw` из демки (в CS стрейфы постоянны, и без
этого модель «моонвокала»); октант считается циркулярным средним по сегменту, разворот
внутри одного бега режет сегмент. Скорость воспроизведения — `speed / эталон` клипа.

**Оружие в руках.** Из колонки `weapon` строятся интервалы «какой ствол когда», и если
модель экспортирована (`models export ak47 m4a1_silencer ...` — `models mapping` сам
добавит `weapon.<имя>` в `ue_mapping.json`), она спавнится и крепится к кости руки
(`weapon_bone`, по умолчанию `hand_R`) attach-треком, с видимостью ровно на свой
интервал. Для чего модели нет — сборка перечислит в логе одной строкой.

Тела игроков поворачиваются **только по yaw** — наклон взгляда не валит модель вперёд.

Отрезки короче 0.25 с поглощаются соседними, иначе анимации мигали бы на каждом шаге.
Клипы подбираются по именам анимаций модели; если модель называет их иначе — поправьте
`ue_mapping.json`:

```json
{ "player.CT": {
    "skeletal_mesh": "/Game/cs2toUE/Models/ctm_sas/ctm_sas.ctm_sas",
    "animations": { "idle": "...", "walk": "...", "run": "...", "death": "..." } },
  "player.TERRORIST": { "skeletal_mesh": "...", "animations": {} },
  "grenade": "/Engine/BasicShapes/Sphere.Sphere",
  "default": "/Engine/BasicShapes/Cylinder.Cylinder" }
```

## Эффекты

Считаются при экспорте и кладутся в `scene.json` отдельным списком:

| эффект | откуда | время жизни |
|---|---|---|
| дым | `smokegrenade_detonate` | до `smokegrenade_expired`, иначе 18 с |
| молотов | `inferno_startburn` | до `inferno_expire`, иначе 7 с |
| взрыв HE | `hegrenade_detonate` | 0.7 с |
| флешка | `flashbang_detonate` | 0.5 с |
| обманка | `decoy_started` | 15 с |
| взрыв бомбы | `bomb_exploded` | 1.5 с |
| трассер | `weapon_fire` | 0.06 с |

Позиция ищется по цепочке: координаты из события → последняя точка траектории самой
гранаты (по `entityid`) → позиция бросившего. Трассер идёт от глаз стрелка вдоль взгляда
на 3000 юнитов, но **если выстрелом кого-то убили — луч заканчивается на теле**.

В Unreal каждый эффект — актор с треком видимости, включающимся ровно на своё время. Если
в `ue_mapping.json` указана система Niagara, будет она; если нет — примитив нужного
размера (радиус дыма 144 юнита и т. д.), чтобы сцену можно было смотреть сразу:

```json
{ "effect.smoke":   "/Game/FX/NS_Smoke.NS_Smoke",
  "effect.molotov": "/Game/FX/NS_Fire.NS_Fire",
  "effect.tracer":  "/Game/FX/NS_Tracer.NS_Tracer" }
```

Выстрелов в раунде бывают сотни, поэтому есть предохранители: `--no-tracers`,
`--no-effects`, `--max-effects` (по умолчанию 1500). Если предел сработал, скрипт пишет в
лог, сколько пропущено — молча не режет.

## Unreal Engine

Папку с движком и проект указываете вы. Программа только подсказывает, что нашла (реестр
Epic, манифест лаунчера, папки `UE_*` на всех дисках) — сама ничего не выбирает, потому
что на машине легко стоит несколько версий движка.

```bat
cs2toue-cli.exe ue detect                                 :: что найдено
cs2toue-cli.exe ue set --engine "S:\ue5\UE_5.5"           :: папка, внутри которой Engine\Binaries
cs2toue-cli.exe ue set --project "S:\work\My.uproject"
cs2toue-cli.exe ue build <сцена>                          :: собрать Level Sequence
cs2toue-cli.exe ue map de_dust2                           :: импортировать карту
cs2toue-cli.exe ue models --scene <сцена>                 :: импортировать модели
cs2toue-cli.exe ue build <сцена> --dry-run                :: показать команду, не запуская
```

```bat
cs2toue-cli.exe ue render <сцена>                     :: рендер секвенции в PNG-кадры
cs2toue-cli.exe ue render <сцена> --res 2560x1440 --quality final --format exr
cs2toue-cli.exe ue render <сцена> --level /Game/MyMap.MyMap
```

`render` гонит собранную секвенцию через Movie Render Queue в offscreen-режиме: PNG/JPG/EXR
кадры ложатся в `<сцена>
ender`, кодировать в видео — дело монтажки. `--quality preview` —
черновик в один сэмпл, `final` — 7 темпоральных сэмплов. Проверено вживую: 468 кадров
720p из реальной демки за 7,5 минут на GTX 1650.

Что делает `build`: создаёт Level Sequence, спавнит актора на каждого игрока и гранату,
кладёт transform-треки (с разворачиванием углов, чтобы Sequencer не крутил актора через
360°), скрывает мёртвых, ставит CineCamera с камерным катом и фокусным расстоянием из FOV,
расставляет эффекты и помечает раунды и убийства маркерами на таймлайне.

Флаги: `--package=/Game/cs2toUE`, `--name`, `--scale`, `--no-effects`, `--no-tracers`,
`--no-animations`, `--max-effects`.

Ручной путь, если движок не указан:

```
UnrealEditor-Cmd.exe "MyProject.uproject" -run=pythonscript ^
  -script="...\ue\build_sequence.py <сцена> --scale=2.54"
```

или в редакторе, в консоли Python:

```python
import sys; sys.argv = ["build_sequence.py", r"S:\...\exports\match_clip1"]
exec(open(r"S:\Programs\cs2toUE\ue\build_sequence.py").read())
```

## Демки CS:GO

Прямого пути «данные → Unreal» для Source 1 нет: `demoparser2` — парсер CS2. Для CS:GO
работает классический маршрут HLAE:

1. `cs2toue-cli.exe hlae resolve demo.dem` — узнать версию HLAE с `AfxHookSource`.
2. Запустить демку в клиенте CS:GO (ветка `csgo_legacy`) через этот HLAE.
3. Записать `mirv_agr record` (AGR) или `mirv_camio export`.
4. Импортировать в Blender через
   [afx-blender-scripts](https://github.com/advancedfx/afx-blender-scripts), оттуда
   FBX → Unreal.

Заголовок такой демки программа читает и версию HLAE подбирает — этого достаточно, чтобы
не гадать, какой билд качать.

Что дал сквозной прогон (клип 14,6 с, de_vertigo):

| шаг | результат |
|---|---|
| экспорт сцены | 23 актора, 16 134 ключа, 99 эффектов |
| модели | 2 агента × 108 анимаций, 10 стволов |
| анимации | 22 сегмента движения, ни одного без клипа |
| оружие | 18 стволов привязано к кости руки |
| рендер | 468 кадров 720p за 41 секунду |

Сборка идёт через полноценный редактор в offscreen-режиме: первый запуск проекта
компилирует шейдеры (десятки минут, одноразово — кэш ложится в workspace), дальше —
пара минут. Импорт моделей и карт в проект — самая долгая операция, потому что Unreal
строит каждый ассет; повторный импорт того, что уже в проекте, пропускается.

Где программа деградирует вместо падения: нет ассета — ставится примитив, нет клипа для
состояния — берётся `idle`, недоступно свойство в демке — пропускается с предупреждением,
не найден меш по указанному пути — ищется в пакете средствами самого Unreal.

Проверки без демки лежат в `tools\`:

```bat
python tools\make_test_demo.py     :: синтетические заголовки демок CS2 и CS:GO
python tools\test_effects.py       :: позиции и время жизни эффектов, геометрия трассеров
```

## Если что-то не так

**`cs2.exe не найден`** — укажите игру:
`cs2toue-cli.exe setup --cs2-exe "D:\Steam\steamapps\common\Counter-Strike Global Offensive\game\bin\win64\cs2.exe"`

**`demoparser2 is not installed`** — переустановите программу из `cs2toUE-Setup.exe`; запускать нужно
`cs2toUE.exe` или `cs2toue-cli.exe` из папки установки — Python внутри них.

**Карта не находится** —
`cs2toue-cli.exe maps list --cs2-dir "<папка Counter-Strike Global Offensive>"`.

**HLAE стартует, но CS2 не открывается** — посмотрите `cs2toue-cli.exe play demo.dem --dry-run`:
в команде должны быть `-programPath` на ваш `cs2.exe` и переменные `SteamPath`,
`SteamAppId=730`. Не заходите на VAC-сервера с загруженным HLAE.

**Индекс HLAE устарел** — `cs2toue-cli.exe hlae refresh`.

**Unreal не запускается из программы** — `cs2toue-cli.exe ue detect`, затем `ue set --engine`
и `ue set --project`. Проверить команду можно через `ue build <сцена> --dry-run`.

**Мало места на C** — программа туда не пишет; если Python ставится сама, он тоже уходит
в папку программы.
